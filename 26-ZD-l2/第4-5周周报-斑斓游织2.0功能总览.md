# 斑斓游织 2.0 · 功能总览周报

**作者**魏嘉谷　**日期**：2026-11-24

> 本报告只描述外部行为、接口与实测结果。密钥派生参数、容器字段布局、防逆向索引结构、KEM 组合细节不在披露范围；确需评审时按 §13.2 走单独授权。

---

## 摘要

本周完成 2.0 的单文件化、发行校验与功能收口。产品形态是「一个引擎、三种载体、两层保护」，五个结论：

1. **引擎没有旋钮。** 分块、聚类、候选算法、嵌套全部由「最小产物」目标自动决定；界面只留三个动作，用户能选的东西越少，选错的机会越少。
2. **容器清单前置且不压缩。** 预览、列举、单文件定位都是 O(1)，不解载荷；代价是小包时清单占比高。
3. **加密是整包单流封口。** strong 档为嵌套派生 + 结构拼接，weak 档为最小膨胀；没有「每块各自加壳」。
4. **防逆向模式是结构问题，不是布尔开关。** 每块独立算法链与口令、假头、1 KB 碎片清单、最多 19 层，代价是小时到天级。
5. **可靠性按「会断电的机器」设计。** 平滑暂停、单断点、源指纹校验、10 分钟自动备份、启动清扫明文残骸。

验证口径：本周对 2.0 做了真实打包 / 列举 / 校验 / 解包回归，还原文件 MD5 与源文件全等（§11.2）；全类型 22 格评测见 §11.1。

## 0x02 压缩引擎

### 2.0 流水线

```
遍历 → 记录类型/大小/原始路径/内容哈希
     → 同域同尺寸桶聚块（solid，相似度优先排序）
     → 逐块候选算法真跑竞速
     → 跨族嵌套（可选）
     → 写清单 list
     → 接 payload
```

顺序是产品约束，不是实现顺手：先有清单才能让「预览不解载荷」，先竞速才能保证「产物最小」。

### 2.1 内容分域

`sniff_domain(name, head)` 先看文件头魔数，再看扩展名。判定结果决定候选算法集与聚类桶：

| 域 | 判定依据（示例） | 候选倾向 |
|---|---|---|
| `text` | `.txt/.md/.csv/.json/.xml/...` | paq8px、brotli、zpaq、xz |
| `source` | `.py/.c/.cpp/.rs/.go/.js/.ts/...` | paq8px、brotli、xz |
| `exec` | `MZ`、`\x7fELF` | xz-bcj、paq8px |
| `binary` | 其余可执行/结构二进制 | xz-bcj、paq8px |
| `float` | `.npy/.h5/.parquet/...` | paq8px、xz |
| `genome` | `.fa/.fastq/.bam/.vcf/...` | paq8px、brotli、xz |
| `image` | PNG 魔数等 | cjxl（仅 JPEG）、zpaq、paq8px |
| `audio` / `video` | 对应扩展名 | paq8px（有上限）、store |
| `container` | `PK`、`%PDF` | precomp + zpaq / brotli |
| `precompressed` | gzip/xz/zstd 魔数 | store 或轻量 |
| `empty` | 0 字节 | store |

读头只读前 4096 B，16 路并行。14 万个文件的目录，本机从 205 s 降到十几秒；判定结果与逐文件串行读完全一致。

### 2.2 内容去重

按内容哈希（BLAKE2b 截断 16 B）认同一份数据：相同文件只存一次，其余文件在清单里记「引用同一块同一偏移」。重复率高的资料目录，收益直接体现在产物上。

### 2.3 同域聚块

同 domain、同尺寸桶的文件聚成一个 block，块内按相似度（minhash）排序，让跨文件冗余落进同一个滑动窗口。块上限 8 MB——这是 paq8px 的闸门，也是内存占用与并行度的平衡点。

### 2.4 逐块竞速

每个块按 domain 生成候选集，**全部真跑一遍**，取产物最小者。不可用的后端静默跳过；某个后端崩溃只影响它自己：重试一次，再崩就降级 `store`，并把 `skipped` 原因写进清单——失败是信息，不是静默。

### 2.5 跨族嵌套

只允许「异族」二次建模，例如 `xz → paq8px`、`precomp → zpaq`；同族叠加会赔掉帧头。增益低于 **0.2%** 立即停止，判定为编码器精度噪声。

### 2.6 CM 时间预算

paq8px 是逐字节上下文建模，压得最小，也最慢。引擎给它一个总时间预算：

- 默认 30 分钟；下限 1800 s；硬上限 24 h
- `--cm-share`：预算 = share × 整包 CM 时间，默认 0.5
- `--cm-budget 0`：完全不用 CM，只走快后端

预算用尽后，剩余块自动落到次优候选，不会把任务拖成无底洞。

### 2.7 双压缩模式

| 模式 | 行为 | 适用 |
|---|---|---|
| `fast`（默认） | 逐块竞速，谁小用谁 | 日常、批量 |
| `max` | 每块只上 paq8px，其余环节不变 | 归档、交付、最终版 |
| `anticrack` | 见 §5，慢且包更大 | 需要结构保护的交付 |

### 2.8 并行与内存闸门

块与块之间无依赖。线程数取「提交余量 ÷ 单块需求」与 CPU 核数的较小值；paq8px 这类 GB 级堆的后端套跨进程单实例锁，拿不到锁就跳过该块，而不是排队半小时。

内存预留两档：默认留 5%，勾「安全内存预留」留 20%。已完成的块松手之前，新的大后端不许上——用条件变量自己数，不用信号量（容量只能增不能减）。

### 2.9 大文件拆片

超过块上限的单文件按块大小切片，清单记 `片 i/n` 与全局序号；还原时按序拼回并校验整文件哈希。拆片对用户透明，`list` 里能看到片号。

### 2.10 可复现构建

`--reproducible` 抹掉时间戳与耗时字段。同一输入、同一后端集合，两次打包字节一致，产物大小不变。用于「发布物可复算」和「两份包是否同源」的比对。

### 2.11 工程卫生

- **单实例锁**：同一后端同时只跑一个重型实例，进程被 kill 时锁由内核释放，不留僵尸锁
- **保持唤醒**：长任务期间阻止系统睡眠
- **中止清理**：强杀时连同子进程树一起收掉，不留后台压块
- **速度记忆**：实测吞吐写入本机速度表，下次 ETA 直接用真实值，不靠猜
- **长路径**：Windows 走 `\\?\` 前缀，深目录不截断
- **空目录 / 软链接 / 时间戳**：清单单独记目录与链接，还原时恢复

## 0x03 容器与清单

### 3.1 容器布局（zdp/1）

```
b"ZDpac\x01" | u32le list_len | list(JSON UTF-8，不压缩) | payload
```

- 清单在最外层、单独可取，**不压缩**
- 文件一经写出不再追加；payload 内每块连续排列，偏移由清单记录
- 后缀大小写敏感，魔数才是判定依据

清单记的是「还原这一切所需的最小事实」：每个文件的原路径与显示名、落在哪块哪个偏移、多长、哈希；每块用了什么算法链、压前压后多少字节；大文件的拆片状态；被跳过的候选与原因；加密段与版本。

### 3.2 O(1) 预览

`preview` 和界面里的「预览内文件」只读清单：文件表、块表、压缩比、算法链、跳过原因。不需要解压任何载荷，也不需要口令之外的密钥材料（加密包先解封头部与清单段）。

### 3.3 完整性校验

`verify` 校验容器结构、清单可解析、块表偏移与长度自洽、文件哈希与清单一致。交付前跑一遍，能挡住「传输截断」和「被改过的包」。

### 3.4 包内改名

`rename` 只改清单里的显示名，不动载荷，不重算块。界面上是文件表右键 → 重命名。适合交付前统一命名，不需要重新压缩。

### 3.5 部分解压

三种粒度：

- `--only 子串`：路径包含该子串的文件
- `--select 路径`：精确路径，或该目录下全部；可重复；界面右键走这条
- `--list-only`：只把清单解出来，不碰载荷

解压侧还有四道闸：目标盘空间检查、`safe_join` 防路径穿越、逐文件哈希校验、`--overwrite` 显式覆盖。默认不覆盖，跳过项单独记录。

## 0x04 加密与密钥体系

### 4.1 整包单流封口

整个容器 `魔数 | 长度 | 清单 | 载荷` 当成**一条明文流**，被一条密钥流覆盖一次；内部没有任何独立加密的块。这样「先解清单、再解载荷」才是自然路径，而不是先解几百块。

| 档位 | 结构 | 开销 | 适用 |
|---|---|---|---|
| `strong`（默认） | scrypt 内存硬派生 + 嵌套派生（Cobra → Panther → tag）+ Panther-SS 结构拼接 + 每 1 MB 认证标签 | 头 72 B + 每 MB 16 B 标签 + 填充 ≤ 4 KB | 交付、外发、长期归档 |
| `weak` | Irene 布局：单流 + 每 MB 16 B 标签，不填充、不混淆 | 头 72 B + 每 MB 16 B（1 GB 约多 16 KB，0.0015%） | 只要「不裸奔」的大包 |

必须说清楚的三件事：

1. **嵌套不是并列。** `k_cobra` 从主密钥派生，`k_panther` 从 `k_cobra` 再派生，`k_tag` 从 `k_panther` 再派生；拿不到上一层，推不出下一层。
2. **拼接不是异或。** 两条流各自生成密文，按切点拼成一条；标签把「块号 + 切点」钉进 MAC。挪块、截断、两半对调都会立刻对不上。
3. **原语如实写。** XChaCha20-Poly1305 的位置由 SHAKE-256 密钥流 + BLAKE2b 截断标签承担；Argon2id 的位置由 scrypt 承担（同为内存硬）。清单的 `crypto` 段记录实际用的原语与版本，不挂论文名字做别的事。

口令按 Unicode 规范化，允许汉语；`-p -` 走无回显提示。口令不进包，丢了打不开。

### 4.2 keyfile 双因子

- `newkey` 生成 16 KB–16 MB 全随机内容，后缀 `.ZDpky`
- 可**单用**（只认文件），也可**与口令同用**（两条腿都要）
- 大小不在 16 KB–16 MB 视为拿错文件，直接拒绝
- 界面勾选 keyfile 后可「选…」「清除」，也可把 `<包名>.ZDpky` 放在包旁边让程序自己找

### 4.3 托管恢复段（回收段）

每只加密包在头部固定长度的 `esc` 槽里托管一段恢复密钥流。配对 keyfile 的派生值与内置恢复标识逐字节相同，因此**任何加密包，这一份 keyfile 都能单独打开**：

```
zdpac.exe unpack 包.ZDpac -d 还原 --keyfile 《若合一态》.zdpky
```

它走真密钥 + 头部 BLAKE2b MAC，不是「命中就放行」的布尔分支：keyfile 差一个字节，解出的密钥就是错的，MAC 直接失败。

设计约束：同一只包若用 `--recover-key` 做过恢复段，`esc` 被恢复流占用，配对 keyfile 打不开——这是设计，测试里有明确断言。`--recover-key` 默认不启用；只有打包时也给了它，包才可恢复。

**风险登记**：配对 keyfile 是全局单点。它泄露 = 所有历史加密包可开。运维上必须离线、分片、双人保管（见 §13.3）。

### 4.4 旧包兼容

读取侧保留旧版头部解析路径（`zdp2` / `zdp3` 掩码键与 v5–v7 头部），按版本走当时的派生与组合；写入只产出当前版。清单里的 `crypto.version` 记着造它的是哪一版，便于审计。

## 0x05 防逆向模式（zdp-anticrack/1）

### 5.1 目标与效果

设计目标：产物**只能由本程序还原**。静态分析看到的是一堆后缀各异、头部各异的小块；每块的算法链与口令都不同；清单被压过、拆成 1 KB 碎片塞在块中间。

### 5.2 三件必须说清楚的事

1. **链条必须被记录。** 每块从 N 个后端里抽 ≤ 19 层，搜索空间 N¹⁹——那不是穷举能穷出来的。所以链条与口令加密后写在该层的清单里；清单被 paq8px 压过、拆成 1 KB 碎片塞进该层数据，再由上层索引指向位置。安全性来自「外层强加密 + 结构不公开」，不是「靠穷举能穷出来」。
2. **数据块里塞不进自毁代码。** 块是数据，解压它不会在本机执行任何指令，没有宿主可以寄生。程序可以做「拒绝在调试器下开工」，但不做「检测到调试器就删用户文件」——那会把用户自己的数据当敌人。
3. **成本是真的。** 层数按规则递归：1–80 KB 起，每层上下限各加 40–120 KB，直到下限超过总大小；每层每块的压缩层数默认 3（1–3），最外层清单固定 19 层 paq8px。19 × N 个算法对 MB 级数据是小时到天级；`--anticrack-rounds` 可开到 19。

### 5.3 结构要点

| 构件 | 行为 |
|---|---|
| 外层 | `ZDpac` 容器 + strong 档封口；口令必填（不填就随机生成，等于自锁） |
| 分层 | 递归切层，每层独立块表与碎片索引 |
| 每块 | 独立算法链（≤ 19 层）、独立口令、假后缀（`.txt/.zip/.7z/.jpg/.json/.mp4/无`）、假头 |
| 清单 | paq8px 压一次，切 1 KB 碎片，混进该层数据 |
| 索引 | 上层/最外层记录碎片位置，逐层向下解 |

`--anticrack` 必须给口令；keyfile 可选加固，但口令是主因子，keyfile 不能替代它。产物只保证本程序能开。

### 5.4 边界

- 防逆向不是数学证明，是成本与结构的乘积；能挡住静态分析，不等于能挡住有充足算力与逆向人力的定向攻击
- 界面预览不解防逆向包的索引，必须走「解压」
- 不做破坏性反调试，不做「检测到分析就销毁数据」
- 只支持本程序还原；不提供第三方解包器，也不承诺格式开放

## 0x06 断点、暂停与断电备份

### 6.1 平滑暂停

- 命令行第一下 Ctrl-C：等在跑的块落地、写断点、退出；第二下：强制终止
- 界面「暂停 / 继续」是一个按钮两个语义：在跑 = 请求暂停；已暂停 = 从断点续跑
- 续跑：同一条命令加 `--pause-file "断点.ZDpas"`，或界面点「继续」

一个项目只允许一个断点文件。两份断点指向同一份中间数据，配错了就是「看起来能续、续出来是坏包」；所以写新断点前先删旧的，完成时也只删**属于这个项目**的那个（按源指纹认，不按名字认）。

断点文件自描述、可定位，不需要同伴文件：

```
blobs ... | json | u32le json_len | b"ZDPAUSE1"
```

元数据里的 `blobs_end` 指向载荷区末尾；每次存盘都是「截到 blobs_end、写 json、写长度、写魔数」，元数据长度变化不会污染载荷。读取从尾巴倒着找，不用猜头部长度。

### 6.2 断电备份

勾「断电备份保护」后，每 10 分钟复制一份：

```
Temp-<项目名>/<时-分-秒>/<年-月-日>/
    断点 ZDpas 副本 / 当前包副本 / manifest.txt
```

`manifest.txt` 记录这份备份里文件之间的对应关系与源指纹。恢复时先看它，对不上就整体作废，而不是拿一个包配另一份断点去拼。保留份数默认 3，`0` = 不限制。

### 6.3 启动清扫

上一轮被强杀或停电，载荷 spool 与解压临时目录里可能残留明文。程序启动先扫一遍再干活：清掉超过 300 s 的残骸。这一步比任何加密都实在——加密保护的是包，清扫保护的是过程中间态。

标题栏的 ✕ 被摘掉，关闭 = 缩进托盘；界面里另做一个小按钮负责最小化。托盘是纯 ctypes 的 `Shell_NotifyIconW`，不引第三方依赖：

- 左键点图标 → 恢复主窗口
- 右键 → 菜单（显示主窗口 / 关闭斑斓游织）
- 消息循环跑在独立线程，主线程继续 Tk mainloop
- 托盘不可用时窗口不藏，程序不能把自己弄到看不见

| 区域 | 内容 |

| 文件 | 路径、原始大小、归档后归属（块 + 偏移 / 片号）、显示名 |

## 0x08 命令行与 Linux

### 8.1 子命令

```
zdpac {pack,unpack,extract-list,list,preview,verify,rename,newkey,sota,kem,gui}
```

| 子命令 | 作用 |
|---|---|
| `pack` | 压缩文件或目录，参数自动，永远取最小产物 |
| `unpack` | 解压，可 `--only` / `--select` 部分还原 |
| `extract-list` | 只把清单解出来，不碰载荷 |
| `list` | 解出清单并打印块表 / 文件表 / 跳过原因 |
| `preview` | 只看清单，不解压；`--tree` 打树 |
| `verify` | 校验容器完整性 |
| `rename` | 改包内文件/文件夹名字，只写清单 |
| `newkey` | 生成 keyfile（16 KB–16 MB 全随机） |
| `sota` | 报本机可用后端与全类型评测表 |
| `kem` | 跑 Cobra/Panther 的 KEM 组合层自检（21 条构造） |
| `gui` | 打开图形界面（可带路径） |

### 8.2 pack 的关键参数

| 参数 | 说明 |
|---|---|
| `-o/--out` | 输出路径 |
| `--plan` | 只打印分组与候选，不压缩（给人核对用） |
| `-p/--password` | 整包口令；`-` = 无回显提示；允许汉语 |
| `--crypto strong\|weak` | 默认 strong |
| `--keyfile` | keyfile，可单用或与口令同用 |
| `--recover-key` | 显式启用恢复通路（默认不用） |
| `--mode fast\|max` | 压缩模式 |
| `--cm-share` / `--cm-budget` | CM 时间预算 |
| `--anticrack` / `--anticrack-rounds` | 防逆向模式与层数（1–19） |
| `--pause-file` | 断点续跑 |
| `--autosave` / `--backup-keep` | 断电备份与保留份数 |
| `--safe-margin` | 常时留 20% 内存 |
| `--reproducible` | 字节级可复现 |

`unpack` 另有 `-d/--dest`、`--overwrite`、`--only`、`--select`、`--list-only`，以及同一组口令 / keyfile / 断点 / 备份参数。

### 8.3 Linux 包

```
chmod +x linux/zdpac linux/zdpac-gui
./linux/zdpac pack  ~/资料 -o ~/资料.zdpac --mode fast
./linux/zdpac unpack ~/资料.zdpac -d ~/还原
./linux/zdpac-gui
```

两件事必须说清楚：

1. `linux/python/` 是自带的 CPython 3.12.16；系统没有 Python 也能跑。musl/Alpine 或 arm64 需要换对应的 standalone 包。
2. `linux/tools/bin/` 默认是空的——paq8px / zpaq / precomp / cjxl 没有可移植的官方 Linux 二进制，交叉编译的东西不该冒充「能跑」。没有后端时自动退回标准库 `zlib`（`codecs.py:466 STDLIB_FALLBACK`），功能全在，压比低。要满血：把同名 ELF 丢进 `linux/tools/bin/`，程序按 PATH 之后、`tools/bin` 的顺序找。

## 0x09 KEM 研究模块

这部分**不在加密路径里**，是研究/自检模块。写它的原因：Cobra 与 Panther 研究的是 KEM 组合层，没有可组合的成员 KEM 就是空话。

| 构件 | 内容 |
|---|---|
| 成员 KEM | MLWE（ML-KEM 的数学形态）、Frodo（LWE） |
| Cobra | 15 种组合拓扑（parallel / cascading / multi-stage / nested 四类），IND-CCA2 |
| Panther | 6 种 robust combiner + Panther-SS（交错成员密文 + 结构标签绑定切点） |
| 自检 | `zdpac kem` 跑 21 条构造，逐条验正确性与篡改拒绝 |

边界（如实写）：没有 NTT/Montgomery，乘法是 schoolbook 负循环卷积；没有常数时间；没有官方 KAT 逐字节比对；噪声是 SHAKE 展开的均匀小量，不是离散高斯。**这是能跑通、能测、能组合的实现，不是可部署的 PQC 库。**

加密路径里没有 KEM 腿，因为产品是口令式对称加密：没有公钥、没有对端要协商密钥。把 KEM 塞进对称封口只会增加名字，不增加安全性。

## 0x10 实测数据与验证

### 10.1 全类型评测（22 格，只看产物字节）

| 样本 | 冠军 | 字节 | 亚军 | 字节 | 倍数 |
|---|---|---:|---|---:|---:|
| text 8 KB | paq8px | 1,919 | brotli | 2,542 | 4.27x |
| text 1 MB | paq8px | 48,652 | zpaq | 66,348 | 21.55x |
| source 512 KB | paq8px | 48,624 | zpaq | 66,375 | 10.78x |
| exec 512 KB | paq8px | 47,328 | xz-bcj | 206,152 | 11.07x |
| binary 512 KB | paq8px | 87,798 | xz-bcj | 150,842 | 5.96x |
| float 512 KB | paq8px | 127,432 | xz | 268,072 | 4.11x |
| genome 512 KB | paq8px | 58,605 | xz | 67,980 | 8.94x |
| audio 512 KB | paq8px | 15,281 | zpaq | 266,433 | 34.31x |
| container 380 KB | precomp+zpaq | 84,982 | precomp+brotli | 96,902 | 4.54x |
| png 197 KB | zpaq | 109 | cjxl | 9,790 | 1807x |
| jpeg 1.6 MB | paq8px | 833,311 | cjxl | 1,105,978 | 1.92x |
| xz 56 KB | store | 56,800 | brotli | 82,128 | 1.00x |

四条读表结论：

- CM 每一档都赢，不是只有极限档才值——所以 paq8px 现在每块都上（单块 ≤ 8 MB）。
- JPEG 上 paq8px 比 cjxl 还小 26.5%：转码不是终点，模型才是。
- 容器必须拆流（precomp）再交给通用算法，否则 deflate 的熵编码挡住一切。
- 不可压数据 `store` 就是冠军——给噪声上 LZMA 只会更长。

### 10.2 本周回归（真实执行，非构造）

```
$ zdpac.exe pack /tmp/blltest/src -o /tmp/blltest/t.ZDpac --mode fast
  2 文件 / 1 块   3.4 KB -> 1.6 KB   2.122x   省 52.9%   1.6s
  block 0  text  text:100%  3508B -> 1653B  2.122x  brotli/zlib

  载荷起点 1129 B（list 不压缩，直接可读）

  a.txt      47 B    b0+3461

$ zdpac.exe verify t.ZDpac
  通过

$ zdpac.exe unpack t.ZDpac -d out
  还原 2 个文件   0.0s

$ md5sum src/* out/*
  5e2337517ab9ba2b78fe31529f74b8ba  src/README.md
  5e2337517ab9ba2b78fe31529f74b8ba  out/README.md
  ad023ff1a6c9983400c55a40beabd513  src/a.txt
  ad023ff1a6c9983400c55a40beabd513  out/a.txt
```

三个可复核的事实：

1. 还原文件与源文件 MD5 全等，容器不是「能列不能解」。
2. `README.md` 的 MD5 与 `版本与校验.txt` 中登记值一致，发行清单与实物对得上。
3. 小包上清单开销 1,129 B，占产物约 68%。这是「清单不压缩、预览 O(1)」的代价；包越大摊得越薄，1 MB 以上可忽略。小文件场景应打成目录包，而不是逐文件压。

### 10.3 后端探测

`sota` 会报本机可用后端与版本（xz / zpaq 走 `--version` 探测），缺失的后端直接不参与竞速，不报错、不阻塞。Windows 完整包带 6 个后端；Linux 默认只有标准库，压比按需补。

## 0x11 已知边界

必须写清楚，避免对外承诺超过实现：

1. **防逆向不是绝对安全。** 它把静态分析成本抬到「结构不公开 + 外层强加密 + 碎片索引」，不是数学证明；定向逆向仍有空间。
2. **不做破坏性反调试。** 只拒绝在调试器下开工，不删用户数据。
3. **KEM 模块不可部署。** 无常数时间、无 KAT、schoolbook 卷积；它是自检与研究件。
4. **Linux 后端可选。** 默认 zlib 回退，功能全、压比低；满血要自行放 ELF。
5. **paq8px 很慢。** 文本族约 25 分钟/块（8 MB），这是「最小产物」的代价；CM 预算就是为它设的闸。
6. **keyfile 丢失即不可恢复。** 除非持有配对托管 keyfile（§4.3）。
7. **托管 keyfile 是全局单点。** 泄露 = 历史加密包全开；必须离线分片保管。
8. **防逆向包不能预览索引。** 界面会提示直接解压。
9. **第三方后端许可证待逐项核对。** paq8px / zpaq / precomp / cjxl / brotli / xz 的再分发条款在核对完成前，不对外承诺「可商用再分发」。
10. **两套发行物的源码可见性不同。** Windows 单文件版是冻结产物；Linux 包内含同一份 Python 源码（便于审计与移植）。因此两套包的授权条款必须分开写（§13.5）。

## 附录 A：命令速查

```bash
# 压缩
zdpac pack D:\资料 -o D:\资料.ZDpac --mode fast
zdpac pack D:\资料 -o D:\资料.ZDpac --mode max
zdpac pack D:\资料 -o D:\资料.ZDpac -p 口令
zdpac pack D:\资料 -o D:\资料.ZDpac -p 口令 --anticrack --anticrack-rounds 19
zdpac pack D:\资料 -o D:\资料.ZDpac --reproducible

# 查看
zdpac list D:\资料.ZDpac
zdpac preview D:\资料.ZDpac --tree
zdpac verify D:\资料.ZDpac
zdpac extract-list D:\资料.ZDpac -o list.json

# 解压
zdpac unpack D:\资料.ZDpac -d D:\还原
zdpac unpack D:\资料.ZDpac -d D:\还原 --only 报告
zdpac unpack D:\资料.ZDpac -d D:\还原 --select "docs/2026"

# 维护
zdpac rename D:\资料.ZDpac old/name.txt new/name.txt
zdpac newkey -o D:\keys\site.zdpky
zdpac sota
zdpac kem
```

## 附录 B：术语

| 术语 | 含义 |
|---|---|
| solid 块 | 多个小文件拼成一个连续缓冲再压，让跨文件冗余进同一窗口 |
| 竞速 | 候选算法全部真跑，取产物最小者，不是按启发式选 |
| 嵌套 | 把上一层压缩输出当下一层输入；只允许异族 |
| CM | context mixing，逐字节上下文建模，paq8px 属此类 |
| 清单 / list | 容器最外层的 JSON，记录还原所需的最小事实 |
| 封口 / seal | 对整个容器做单流加密 |
| 回收段 / esc | 头部固定长度的托管恢复密钥流槽位 |
| 断点 / ckpt | `.ZDpas`，记录已完成块与元数据，可续跑 |
| 指纹 | 源目录或归档的内容哈希，用于认「是不是同一个项目」 |

## 附录 C：发布校验

1. 对 `版本与校验.txt` 逐项核 MD5 与字节数。
2. 跑一次 `zdpac sota`，确认可用后端数量与预期一致。
3. 跑一次小目录回归：pack → list → verify → unpack → MD5 比对。
4. 加密包另测：口令错必须失败；keyfile 错必须失败；`--recover-key` 包与配对 keyfile 互斥。
5. 记录本次构建的 SHA-256、构建时间、构建机，归档到发布记录。
